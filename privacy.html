本ポリシーは、egyo（以下「開発者」）が提供する egcamera、eglut、egtency、egweight、egsplan、egview、egpamph、QuietBlack、StartMyMac、PairFinder、ExpressGenesis と、このアプリ紹介サイトに適用します。アプリごとの説明には、ロック画面撮影拡張や Widget など付属する機能を含みます。

現在のアプリには、広告 SDK、アクセス解析 SDK、広告目的の追跡、利用者アカウントの登録機能はありません。egsplan は通知機能のため、端末単位の登録を行い、通知条件・通知先・通知予約を開発者のサーバーに保存します。

2. egcamera：写真と撮影設定

  • カメラ画像・撮影した写真：撮影、プレビュー、色の調整に使用します。撮影した DNG／HEIF は端末の写真ライブラリへ保存します。ロック画面撮影では DNG を扱います。
  • 写真ライブラリの画像：許可された範囲の直近保存 DNG を、LUT の仕上がり見本として一時的に読み込みます。取得できない場合は読み取り可能な最新写真を使います。見本は表示専用で、保存済み写真を変更しません。iCloud上の画像は、OSの写真機能を通じて取得する場合があります。開発者へ送信しません。
  • 読み込んだ LUT ファイルと設定：利用者が選んだファイルを端末内へコピーします。同名の登録があれば追加せず、別名のファイルは端末内でSHA-256による内容照合を行います。照合のためにファイルを送信したり、追加のハッシュ一覧を保存したりしません。一覧・選択・並び順、LUT の入力設定、ファイル内の記述や元ファイル名から得た入力解析結果などを保存します。露出や撮影の連番などの設定も端末内に保存します。クラウドのファイルを選んだ場合、ファイルの取得は選択したファイル提供サービスの設定に従います。
  • 端末の傾き：モーションセンサーの重力・向きの情報を水平器に使用します。開発者へ送信せず、行動履歴として保存しません。
  • 保存待ち画像・診断表示：写真ライブラリへ保存するまで、撮影画像をアプリや撮影拡張の保存領域に保留します。保存が成功すると保留分の削除を行い、失敗したものは再保存のために保持します。撮影状態・機種・処理版・LUT名・ファイル名・エラー等の診断ログは直近2,000件を端末内に保存し、再起動後も保持します。設定の「撮影診断」から書き出し・削除でき、自動送信しません。LUTを適用したHEICのメタデータには元LUTファイル名を記録するため、原本を共有するとその名前も含まれる場合があります。

カメラ・写真のアクセスは iOS の許可に従います。写真への追加は保存時に、見本用の読み取り・書き込みは「選択LUTの管理」を開く際に許可を求めます。見本の読み取りを許可しなくても、カメラと写真への追加権限があれば撮影・保存できます。許可は iOS の設定から変更できます。アプリはマイクによる録音や位置情報の取得を行いません。

削除：保存済みの写真は「写真」アプリで、取り込んだ LUT はアプリの管理画面で削除できます。アプリ内の設定や保存待ちデータは、iOS でアプリを削除すると削除されます。「App を取り除く」はデータを残す操作です。写真ライブラリに保存済みの写真は、アプリを削除しても残ります。

3. egtency：計測通信とログ

利用者が宛先を選び計測を開始すると、Cloudflare の 1.1.1.1 または Google の 8.8.8.8 へ、応答時間を測る ICMP Echo（ping）を送ります。IPv6 の経路では、同じ提供元の 2606:4700:4700::1111 または 2001:4860:4860::8888 を使用する場合があります。

この通信では、送信元の公開 IP アドレスや通信の時刻などが、宛先の提供元や経由するネットワークに伝わります。開発者のサーバーを経由する計測ではありません。写真・ヘルスケア情報・コメント・保存済みの計測ログを ping に含めて送信することはありません。宛先の情報の扱いは、各提供元の方針に従います（Cloudflare／Google）。

  • 端末内の記録：計測日時、宛先、応答時間、タイムアウト・エラー、Wi-Fi／モバイル回線などの経路状態、アプリの前面・背面の変化、計測の開始・終了などを CSV に保存します。位置情報や閲覧履歴は取得しません。
  • 表示と通知：宛先や計測結果を Live Activity、Dynamic Island、iOS の計測タスク表示へ渡します。通知は許可された場合に端末上で行います。ロック画面に出す情報は、周囲から見える場合があります。
  • 共有：「計測ログを共有」で選んだ CSV を、利用者が指定するアプリや相手へ渡します。共有しない限り、ログを開発者へ送信することはありません。

停止・削除：「停止」で計測通信を終了できます。保存済みログは次の計測後も残り、計測と停止処理が終了した後の「全消去」、または iOS でのアプリ削除により削除できます。共有済みのコピーは、共有先で別途削除してください。通知や Live Activity の許可は iOS の設定で変更できます。

4. egweight：ヘルスケア情報とコメント

利用者が許可した場合に限り、HealthKit から体重、測定日時・記録の識別情報・記録元、歩数を読み取り、体重の推移、日別の代表値、平均・差分、歩数に応じた表示に使用します。体重や歩数を HealthKit へ書き込む機能はありません。

  • 健康情報：取得した値や計算結果は端末のメモリ内で扱います。アプリ独自の健康情報データベースやサーバーへ保存・送信せず、広告、マーケティング、追跡、第三者への販売に使用しません。アプリ独自に健康情報を iCloud へ保存する機能はありません。
  • 日別コメント：入力した本文、対象日、作成・更新日時を端末内のファイルへ保存します。iOS のファイル保護を使用し、この保存領域はバックアップの対象から除外しています。デモ用と実際の記録用は分けて保存します。
  • 設定・デモ：デモ利用などの設定を端末内に保存します。デモは架空の測定値を使い、HealthKit へ書き込みません。

許可の変更：ヘルスケアまたは iOS の設定から、egweight の体重・歩数の読み取り許可を変更・取り消せます。許可しない情報は表示できない場合があります。

削除と保存期間：コメントは「設定 → コメントの日付別管理」で日付ごとに削除できます。削除するまで端末に残り、同じアプリの再起動や上書き更新では維持します。アプリ削除・再インストール・機種変更では失われ、開発者が復元することはできません。体重・歩数の原本は HealthKit にあり、egweight を削除しても原本は消えません。原本の削除はヘルスケア側で行ってください。

5. egsplan：通知条件・通知先・予定

対戦予定の絞り込みとプッシュ通知のため、開発者が運用する Cloudflare Workers / D1 に端末を登録し、以下の情報を保存します。ログインや Nintendo アカウントとの連携は不要です。

端末の認証情報がない場合、起動・前面への復帰・予定更新など、認証が必要な通信の際に自動登録します。通知をオフにしている場合や、通知条件をまだ保存していない場合も登録が作られることがあります。

  • 通知条件：選択した時間帯・ルール・マッチ・ステージ、通知の有効／無効、開始前の通知タイミング、まとめ通知の時刻を保存し、対象予定の判定と通知予約に使用します。
  • 端末の登録・通知先：端末ごとのランダムな識別子、認証トークンのハッシュ、Apple のプッシュ通知用デバイストークン、通知環境、設定の更新日時を保存します。認証情報は端末の Keychain に保存し、設定や通知先などは端末内にも保持します。
  • 通知予約・送信状態：通知時刻・本文・送信状態・再試行の情報を保存し、Apple Push Notification service（APNs）に通知先と本文を渡して配信します。本文には対戦時刻・ルール・マッチ・ステージ名などが含まれ、ロック画面で周囲から見える場合があります。
  • 接続に伴う情報：通信先の Cloudflare には公開 IP アドレスなどが伝わります。アプリの API は IP アドレスをリクエストの回数制限に使用します。Cloudflare の情報の扱いは同社のポリシーに従います。

対戦予定はサーバーが Splatoon3.ink から取得して保存し、端末の条件と照合します。この取得リクエストには利用者の通知条件やデバイストークンを含めません。アプリは Nintendo アカウント情報、ゲームのプレイ履歴、位置情報、写真、ヘルスケア情報を取得しません。

停止・削除：「通知条件」で通知をオフにして保存すると、未送信の通知予約を停止します。条件自体は保存され、対象予定を確認できます。「接続・情報 → サーバーの登録を削除」で登録削除が成功すると、サーバーの端末登録・条件・通知先・関連する予約を削除します。アプリの削除だけではサーバーの登録は削除されません。通知許可は iOS の設定で変更できます。すでに APNs へ渡した通知は取り消せません。

登録削除時には、端末の Keychain の登録認証情報と保存条件も削除します。接続先と端末内のプッシュ通知用トークンは残ります。画面上の編集中条件は削除直後に残る場合があります。その後に起動・前面への復帰・予定更新などを行うと、新しい端末登録が作られる場合があります。削除した条件はサーバーから復元されません。登録削除は、以後の通信や再登録を禁止する操作ではありません。

保存期間：端末情報と条件は登録削除まで保持します。期限を過ぎた通知予約は7日後を基準に削除し、対戦予定データは更新時に置き換えます。

6. QuietBlack：操作の有無と画面の状態

無操作時間を判定するため、マウスの位置の変化、マウス・キーボードなどのイベント回数や最後の操作からの時間を端末内で確認します。黒画面の表示範囲を決めるためディスプレイ構成を、動画再生などの間に自動表示を保留するため macOS の画面スリープ防止要求の状態を使用します。

入力したキーの文字列、画面の画像、ブラウザ履歴、動画の内容は取得・保存しません。アプリ自身のネットワーク通信、広告、利用状況の自動送信はありません。

保存・終了：待ち時間と自動表示の設定を Mac 内の環境設定に保存します。操作状態は動作中の判定に使用し、操作履歴として保存しません。アプリを終了すると確認処理は止まります。「ログイン時に起動」は macOS が管理します。Mac ではアプリ本体を削除しても環境設定やログイン項目が残る場合があるため、削除前に自動起動を解除してください。設定の削除方法が必要な場合は、下記窓口へお問い合わせください。

7. StartMyMac：接続先・認証情報と実行ログ

ログイン後のネットワーク共有への再接続、アプリ起動、フォルダ表示と、手動の終了時ワークフローのため、Mac のマウント情報と利用者が登録した設定を使用します。終了時は実行中の通常のアプリを確認して終了を要求し、ネットワーク共有の解除を試みた後にディスプレイスリープを要求し、要求完了から5秒後に再要求します。終了拒否や解除失敗はログに残して後続処理を続けます。開発者のサーバーへ設定や実行ログを自動送信する機能はありません。

  • Mac 内の設定：接続先の名前・URL・ユーザー名、有効／無効、起動するアプリと開くフォルダのパス・順序、待機時間などを Mac 内の環境設定に保存します。
  • 認証情報：入力したパスワードは macOS キーチェーンのアプリ専用項目に保存します。設定データや実行ログ、プロセスの引数には埋め込みません。接続時は macOS の接続処理を通じて、指定した共有への認証に使用します。
  • 共有との通信：利用者が指定した NAS・サーバーと接続・認証の通信を行い、通信先や経由するネットワークには接続元のアドレスなどが伝わります。開くフォルダや起動するアプリが行う通信・保存は、それぞれのサービスやアプリの設定に従います。
  • 入力切り替えと通知：入力切り替えを有効にした場合は、アクセシビリティの許可を使って Finder に英数・かなキーを送信します。入力した文章を収集する機能ではありません。通知を許可すると、起動時は処理結果の日時・件数・エラー件数を、終了時は開始の案内と日時を表示します。グローバルショートカットは Ctrl + Shift + W の実行を受け取るために登録し、入力内容を記録しません。
  • 実行ログ：直近の起動時・確認モード・終了時のいずれか1回分をメモリ内に最大500行保持し、次の実行開始時に置き換えます。アプリを終了すると失われます。日時、処理内容、接続先の名前、ボリュームやアプリ・フォルダのパス、終了対象のアプリ名、エラーなどが含まれる場合があります。「ログを書き出す」で選んだ場所にファイルを保存します。開発者へ自動送信しません。

停止・削除：自動起動を止める場合は設定で「ログイン時にStartMyMacを起動」をオフにし、メニューから終了します。保存パスワードは各接続先の「保存パスワードを削除」で削除できます。接続先を一覧から削除して設定を保存した場合も、対応するキーチェーン項目を削除します。パスワード欄を空にして保存するだけでは、保存済みパスワードは削除されません。

1.3以前から1.4以降への更新ではアプリ識別子が変わるため、旧版の設定・保存パスワード・ログイン項目・OS の許可は自動移行しません。旧版に保存した情報は残るため、不要なパスワードやログイン項目は旧版を置き換える前に整理してください。

Mac ではアプリ本体を削除しても、環境設定・キーチェーン項目・書き出したログが残る場合があります。削除前に自動起動と保存パスワードを整理し、書き出したログは保存先で削除してください。環境設定の削除方法が必要な場合は、下記窓口へお問い合わせください。権限は macOS のシステム設定で変更できます。ログを共有する際は、接続先やパスなど不要な情報を除いてください。

8. egview：Tumblr連携と一時キャッシュ

2026年10月25日時点のiOS／iPadOSプロトタイプ0.1.45／認証サービス0.6.1の実装に基づく情報管理を説明します。個人用・開発中のアプリをTestFlightでテストしており、一般配布・試用募集は行っていません。

  • 認可とアカウント：Tumblrの公式OAuth画面で本人がbasic・write・offline_accessを許可し、アカウントと所有ブログを確認します。アプリ内でTumblrのパスワードを収集しません。認可情報は画像と分けて、この端末のみで利用できるKeychainへ保存します。
  • 認証サービス：開発者のCloudflare Workerで認可コードの交換とトークン更新を行います。TumblrのConsumer SecretはWorkerだけで使用します。コード・トークンは交換／更新処理中に扱い、端末への受け渡しには短時間有効な暗号化チケットを使います。更新トークンはWorkerが暗号化した形式で端末へ渡し、更新時にWorkerで復号してTumblrへ送ります。旧形式の接続では更新時に再接続が必要です。認証経路への連続アクセスを抑えるため、通信元IPアドレスからハッシュ化した受付制限用のキーを計算し、Cloudflareの受付制限機能へ渡します。受付制限はIPごとと拠点内の合計に適用します。現行Workerコードはトークン・投稿・アカウント情報をデータベース等へ永続保存しません。Cloudflare側の通信情報等の取り扱いはCloudflareのポリシーに従います。
  • 投稿・画像・動画：ダッシュボード・ライク・所有ブログから取得できるtext／photo／video投稿の画像・直接再生動画、ID、ブログ名、出典、寸法、リブログキー、ライク状態等を閲覧と投稿操作に使用します。投稿一覧と閲覧位置はセッションのメモリ内で管理します。画像は端末内の一時領域へ保存し、取得から72時間・既定200MBの制限を併用します。サムネイルの静止画も端末内で生成・保存し、元データの期限を引き継ぎます。小画像のディスク上限16MBは設定した総上限に含みます。MB上限変更・使用量表示・手動削除を用意し、iCloud Drive同期・端末共有・バックアップの対象にしません。停止中の任意時刻の物理削除は保証できず、起動／復帰等で期限を整理します。
  • Tumblrへの送信：リブログとライク付与・解除は利用者の操作でTumblrへ送信します。リブログは選択した所有ブログのキューへ投稿全体を追加します。新規オリジナル投稿や画像アップロード、追加Matureラベル／NSFWタグの送信は行いません。元ラベル継承は引き続き実機確認中です。
  • 動画：表示・次メディア準備に必要なTumblrの動画配信先（vt.tumblr.com、media.tumblr.com、およびmedia.tumblr.comのサブドメイン）へHTTPSで接続し、AVFoundationでミュートのストリーミング再生を行います。iPad／Duoのデュアルでは左右同時に通信する場合があり、サムネイル用の先頭フレーム抽出でも動画配信先へ接続します。保存する小画像は静止画です。アプリは動画ファイル・オフライン用の動画キャッシュを作りませんが、AVFoundationとOSの一時バッファは使用します。
  • 写真への保存：画像の長押しで保存を選んだ後、写真ライブラリの読み取り・書き込みのフルアクセスを求めます。現在の1枚の圧縮データを再圧縮せず、egviewアルバムへ追加します。限定アクセス・拒否では設定へ案内します。動画保存には対応しません。保存した画像はアプリの一時キャッシュと別管理で、iCloud写真の設定に従います。
  • 診断：利用者が共有操作を選んだ場合に診断メモを共有先へ渡します。OS・件数・キャッシュ量・処理状況等を含み、トークンは含めません。共有内容と送り先を確認してください。投稿URLの個別確認・一覧照合は現行の設定画面には表示せず、内部の回帰検証用処理として保持しています。
  • 接続に伴う情報：Tumblr API・画像／動画配信先・認証サービスへの通信には公開IPアドレス等が伴います。Tumblr側の取り扱いはTumblrのプライバシーポリシーに従います。紹介サイトにはTumblrログイン機能やトークン入力欄を置いていません。

削除とログアウト：設定の「キャッシュを削除」は、この端末の画像ファイル・索引・表示用メモリを削除します。再表示時には必要な画像を再取得します。「ログアウト・この端末の画像を削除」は認可情報もKeychainから削除し、同梱サンプルに戻ります。再接続成功時も以前の画像を削除します。写真ライブラリへ保存した画像、Tumblrへ送ったライク・キュー投稿、外部へ共有したメモは端末のキャッシュ削除やログアウトでは消えません。写真は写真アプリで削除し、写真の許可はiOS設定で変更できます。Tumblr側のアプリ連携解除はTumblrのアカウント設定で行ってください。

9. egpamph：PDF と閲覧記録

利用者が選んだ PDF を表示し、埋め込みWebリンク、印字URL、Web URLを含むQRコードを認識します。PDFの読取・描画・URL／QR認識は端末内で行い、PDFの内容・認識結果・閲覧記録を開発者のサーバーへ自動送信しません。広告・アクセス解析SDKや独自の利用者登録機能はありません。

  • PDFと一時データ：元PDFを変更せず、閲覧用の一時コピーを端末内に作成します。コピーは文書を閉じる・切り替える際に削除し、終了時に残ったものは次回起動時に清掃します。独自の恒久的なPDFライブラリは作りません。
  • 端末内の閲覧記録：最近開いた文書名、日時、総ページ数、文書を識別・再アクセスするための参照情報を直近10件の履歴に保存します。現在ページ・横持ちの表示モードは履歴とは別に文書ごとに保存し、履歴から外れた文書の記録もリセットするまで保持します。ページの送り方向も端末内に保存します。アプリ独自の端末間同期はありません。
  • 外部へのアクセス：iCloud DriveなどのPDFを選んだ場合、OSやファイル提供サービスがファイルを取得するために通信することがあります。Webリンク・URL・QRをタップした場合は、そのURLをOSへ渡し、ブラウザや関連アプリでリンク先へアクセスします。設定内のApple公式ヘルプを開く場合も外部通信が伴います。リンク先やファイル提供サービスにおける情報の扱いは、各サービスの方針に従います。

削除：「設定 → 閲覧記録をリセット」で履歴と全PDFの保存ページ・横持ちモードを消去します。現在開いている文書と送り方向は維持され、以後のページ・モード操作や再オープンから新たに記録します。元PDFは削除しません。元ファイルは「ファイル」アプリや保存先のサービスで管理してください。アプリの削除でアプリ内データを削除できますが、OSのバックアップや外部サービスのコピーは別の管理です。

10. eglut：RAW 写真と補正・LUT

写真ライブラリの RAW を読み、色と階調を調整して 3D LUT（.cube）を生成します。写真の読取・現像・色処理・LUT生成は端末内で行い、原本や写真ライブラリの既存編集を変更しません。開発者のサーバーへ写真や利用情報を自動送信しません。

  • 写真へのアクセス：iOSで許可された写真からRAWを探し、利用者が選んだ原本を取得します。RAW+JPEG／HEIFの組ではRAW側を使います。iCloudにある原本はOSの写真機能を通じて取得するため、通信が必要な場合があります。写真の許可はiOSの設定で変更できます。
  • 端末内の保存：編集再開のため、RAWの識別・再取得に使う参照、ファイル名・形式・内容照合用のハッシュ、補正・スタイル・表示設定等を保存します。最近開いたRAWの履歴は直近10件、共通比較プリセットは3枠で、補正設定と保存時の写真全体の平均色を保持します。自動保存は正常な前世代も残す2世代方式です。アプリ独自のクラウド同期はありません。
  • 名前候補とAI：保存用プレビューの明暗・彩度・暖寒等、被写体分類、補正値を端末内で解析し、対応環境では端末内のFoundation Modelsへ特徴を渡して名前候補を生成します。写真・RAW・GPS・EXIFを外部AIへ送信しません。AIを使えない場合は規則に基づく候補を表示し、利用者が手入力することもできます。
  • LUTの保存・共有：利用者が選んだ名前と色変換の表を.cubeへ保存します。写真そのもの、GPS、RAW現像設定、ICCプロファイル、HDRゲインマップは含みません。「ファイルへ保存」では指定した保存先へ、「保存先を開く」からの共有では選んだアプリへ渡します。iCloud Drive等への保存・共有先での処理は、各サービスと利用者の設定に従います。

削除：「補正を閉じる」を確認すると、現在のRAW参照・補正・最近の履歴を消去し、自動保存の2世代を編集なしの状態に置き換えます。比較3枠と保存済みLUTは残ります。比較枠は長押しして確認後に個別に消去できます。アプリ内データはiOSの「Appを削除」で削除できますが、「Appを取り除く」はデータを残します。元写真と書き出した.cube、共有先やバックアップのコピーは別管理です。写真は「写真」、LUTは「ファイル」や保存先サービスで管理してください。

11. PairFinder：Finder 操作と Mac 内の設定

2026年10月20日時点の0.1.5の実装に基づきます。実際のFinderウィンドウ2枚を連動させるために、アクセシビリティとFinderへのオートメーションを使用します。PairFinder自身がファイルの内容を収集・解析したり、設定・利用情報を開発者のサーバーへ自動送信したりする機能はありません。

  • Mac 内の設定：上下の開始位置（フォルダのURLまたはコンピュータ）、ウィンドウ間の隙間、一組の位置・寸法を環境設定に保存します。フォルダURLには利用者名やフォルダ名が含まれる場合があります。アプリ独自のクラウド同期はありません。
  • Finder の状態と操作：管理対象を識別するため、Finderのプロセス情報とウィンドウID・構造・位置・寸法・最小化状態などを読み、作成した一組の配置・前面表示・開閉を操作します。フルディスクアクセス・入力監視は要求しません。
  • 状態表示・診断：設定画面に状態やエラーを表示し、macOSのログ機能へウィンドウID、操作段階、リサイズ・ホバーの診断情報、エラー等を出力します。エラーにはフォルダ等の情報が含まれる場合があります。OSログの保持・削除はmacOSの管理に従い、アプリ独自の一括削除・書出し機能はありません。ログや画面を共有するときは、不要な名前やパスを除いてください。
  • 共有・クラウド上の場所：Finderでネットワーク共有やクラウド上の場所を開く場合は、Finder・OS・ファイル提供サービスが通信することがあります。Finderでのファイル操作や同期は各サービスと利用者の設定に従います。

停止・変更・削除：「連動を解除」または「PairFinderを終了」で、Finderを残して連動を止めます。これらの操作は開始位置の設定や元ファイルを削除しません。開始位置は設定画面で変更できます。許可はシステム設定の「プライバシーとセキュリティ → アクセシビリティ／オートメーション」で変更できます。Macではアプリ本体を削除しても環境設定やOSログが残る場合があります。設定の削除方法が必要な場合は下記窓口へお問い合わせください。元ファイルはFinderや保存先サービスで管理してください。

12. ExpressGenesis：入力とプロンプトのコピー

創作内容、参考資料のファイル名・役割、希望完成サイズなどを利用者が入力し、日本語の画像生成プロンプトを組み立てます。処理は Mac 内で行い、アプリから ChatGPT や開発者のサーバーへ自動送信する機能はありません。参考画像・音楽・ZIP の読み込み、内容確認、保存、添付も行いません。

  • 保存する設定：明示保存した創作プリセット（非空カテゴリの文章・名前・色）と「出力・仕上げ」の設定をMac内のアプリ設定領域に保存します。プリセットは全ウィンドウで共有し、出力設定は新規画面と次回起動で復元します。これらの保存設定はアプリ独自の暗号化を行わず、端末のバックアップに含まれる場合があります。
  • 未保存の入力と生成文：未保存の創作内容・参考資料の指定・生成文はメモリ内だけで保持し、終了時に破棄します。作業履歴や参考ファイル自体は保存しません。ウィンドウの位置など OS が管理する状態とは区別します。
  • クリップボード：「プロンプト生成」で入力検証に成功すると、生成した文章を macOS の一般クリップボードへ書き込みます。入力エラーでは変更せず、書き込みに成功した場合だけ成功を表示します。終了時にコピー済み文章を消去する機能はありません。0.1.18では、自動コピーをこのMac内へ限定し、ユニバーサルクリップボードによる他のApple端末への転送を抑えます。旧配布版0.1.16にはこの制限がありません。手動コピーや同じMac上の他アプリによる履歴・独自同期は、この制限の対象外です。
  • 利用者による送信・保存：ChatGPT への貼り付け・送信と参考資料の添付は利用者が行います。送信先での情報の扱いは、そのサービスの方針と利用者の設定に従います。別のアプリへ保存・共有した文章や資料、クリップボード側のコピーは、ExpressGenesis を終了しても削除されません。

管理：未保存の入力は各欄で消去するかアプリを終了してください。保存したプリセットは左側の「編集」から削除できます。出力設定は出力・仕上げ画面で変更・出力先削除すると保存内容も更新され、終了だけでは消えません。コピーした文章を残したくない場合は、別の内容をコピーし、利用しているクリップボード履歴も個別に管理してください。ChatGPT に送信済みの会話・添付資料や他の保存先のコピーは、それぞれのサービスやアプリで管理してください。
